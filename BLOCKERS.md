# Production Readiness Blockers

This is the living, fail-closed register of blockers that must be resolved before widespread product use. A blocker is closed only with reproducible evidence; implemented code alone is not sufficient.

## 1. Blocker — Professional baseball pitch tracking

**Status:** BLOCKED — runtime and validation gates are implemented, but production accuracy is not established.

**Remaining work is evidence-driven:** a permission-cleared corpus and a provenance-verified specialist model are prerequisite evidence inputs; the held-out benchmark is the release evidence. No unimplemented product feature is being treated as a substitute for this chain.

### 1.1 Specialist baseball detector model is missing

- The production path supports a dedicated model through `VISION_BASEBALL_OBJECT_MODEL`.
- The repository contains only generic YOLO weights; those are not authorized to release a physical baseball pitch-speed metric.
- A baseball-specific model artifact with documented training-data rights, version, checksum, and reproducible inference configuration is required.

**Close when:** the specialist model is present, configured, versioned, and passes the held-out benchmark below.

### 1.2 Legally cleared training and held-out video corpus is missing

- No commercially admissible public corpus was found with the required pitch footage, ball labels/tracks, and ground truth.
- A Kaggle candidate labelled Apache-2.0 was rejected because its files are explicitly MLB Highlights; the uploader label does not grant MLB broadcast/training rights.
- The corpus must be permission-cleared, with participant releases and an athlete-disjoint held-out split.

**Close when:** a documented, permission-cleared corpus is available with frame-level baseball boxes, track IDs, phase labels, and train/held-out partition evidence.

### 1.3 Professional held-out tracking benchmark has not been run

- The fail-closed benchmark requires at least 500 annotated baseball observations.
- Release thresholds are precision ≥95%, recall ≥95%, and per-phase recall ≥95% across release, flight, plate, and catcher-glove phases.
- It also requires HOTA ≥0.75 and 100 synchronized independent pitch-speed references with P90 error ≤0.67 m/s.
- Free reference collection is supported through the v2 calibrated 240-fps two-phone optical protocol, requiring a measured pitch span, calibration report, and two independent reviewers.

**Close when:** the benchmark runs against the legally cleared athlete-disjoint held-out set and all thresholds pass reproducibly.

### Current verified engineering state

- Native-frame-rate baseball pitch processing is enabled.
- Specialist model routing and 1280px high-resolution inference are implemented.
- Generic models fail closed for physical pitch-speed release.
- Validation manifests and benchmark release gates enforce the evidence requirements.

## 2. Blocker — Sports-object tracking across all canonical classes

**Status:** BLOCKED — YOLO-World detection and a temporal tracker are wired, but no real-world per-class accuracy evidence exists.

### 2.1 Sport-specific prompt routing is implemented

- Soccer, basketball, and baseball now use sport-specific YOLO-World prompts rather than competing against every irrelevant class in the same inference call.
- The pipeline passes its recognized sport into the object detector; unknown sports retain the conservative full canonical prompt set.
- This improves the runtime configuration but is not accuracy evidence.

### 2.2 Per-class held-out tracking benchmark is implemented

- The benchmark independently scores `ball`, `bat`, `hoop`, `goal`, `plate`, `cone`, and `target`.
- Every class requires at least 500 frame-level annotations, precision ≥95%, recall ≥95%, and HOTA ≥0.75.
- A strong ball result cannot conceal failure of another canonical class.
- The application-level capability release gate enforces these per-class values; aggregate object scores alone cannot release the capability.

### 2.3 Legally cleared multi-sport corpus and independent annotations are missing

- Each clip requires a verified source/license, athlete release where applicable, frame-level object boxes, and track IDs.
- The held-out split must be disjoint from tuning/training footage and representative of supported camera angles, lighting, motion blur, occlusion, and object scale.

**Close when:** the per-class benchmark passes on legally cleared held-out footage for all seven canonical objects, with immutable model/version/checksum and corpus provenance evidence.
